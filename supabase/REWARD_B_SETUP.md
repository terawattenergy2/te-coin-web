B ใน **ตั้งค่าระบบ → TC แลกรางวัล** แก้และบันทึกได้ทันทีเมื่อมีระบบสูตร 004 แล้ว ไม่ต้องรัน 007 สำหรับ B รายประเภท เว็บจะเก็บ B เป็นตัวเลขในสูตรปลอดภัย เช่น `ceil(value_baht * 1.5)` ผ่าน `tc_save_formulas` เดิม และอ่าน B กลับจากสูตรเมื่อโหลดใหม่

ฐานข้อมูลรุ่นเดิมปัด TC แลกขึ้นเป็นจำนวนเต็ม หากมี TC พื้นฐานหรือตัวคูณเฉพาะชิ้นใน 005 จะยังใช้ค่าเฉพาะชิ้นนั้นก่อนสูตรรายประเภท ส่วน B แยกเฉพาะชิ้นรุ่นใหม่และ TC ทศนิยมให้ติดตั้ง 007 ตามด้านล่าง

# B สำหรับ TC แลกรางวัล

รัน **007_reward_multipliers.sql ทั้งไฟล์** ใน Supabase SQL Editor แล้วรีเฟรชเว็บ ไฟล์นี้รวมการติดตั้ง 006 ไว้แล้ว จึงใช้ได้ทั้งกรณีเคยรัน 006 และกรณีติดตั้งถึง 004 เท่านั้น (ต้องมี 001, 002, 004 ก่อน)

## ตั้งค่าจากเว็บ

1. ไป **ตั้งค่าระบบ → TC แลกรางวัล**
2. ใส่ B แยกสำหรับ Bundle Set, Cashback/Voucher, Lucky Draw และทัวร์
3. ดูตัวเลขตัวอย่างมูลค่ารางวัล × B และกด **บันทึก B และสูตรแลกรางวัล**

สูตรตั้งต้นใหม่คือ **TC ที่ใช้ = มูลค่ารางวัลเป็นบาท × B สำหรับแลกรางวัล** ปัดขึ้นถึง 0.01 TC เช่น 800 × 1.5 = 1,200 TC และ 800 × 0.5 = 400 TC

ค่าเริ่มต้น B = 1 ทุกประเภท ปรับค่าได้ตามต้องการ เมื่อเปลี่ยน B ในแท็บนี้ สูตรของประเภทนั้นจะเปลี่ยนเป็นสูตรมูลค่า × B ส่วนสูตรขั้นสูงยังเลือกช่องข้อมูลและเครื่องหมายคำนวณเองได้

ถ้าต้องการ B ต่างกันสำหรับรางวัลในประเภทเดียวกัน ไป **แลกรางวัล → จัดการรางวัล → แก้ไข** แล้วใส่ B เฉพาะชิ้น หากเว้นว่างจะใช้ B ของประเภท

B ของรางวัลแยกจาก B สะสมแต้มตามกลุ่มสินค้า และแยกจากอัตราสำรอง Liability การแก้ B รางวัลไม่เปลี่ยนแต้มที่ลูกค้าได้รับตอนซื้อสินค้า

## การเก็บข้อมูล

- B รายประเภท: `tc_settings.membership_config.reward_b`
- B เฉพาะชิ้น: `tc_rewards.redemption_b` (null = ใช้รายประเภท)
- บันทึก B และสูตรพร้อมกันบนเซิร์ฟเวอร์ผ่าน `tc_save_reward_formulas` ตรวจสิทธิ์ Admin และเวอร์ชันสูตร
- คำนวณ TC ที่ใช้จริงบนเซิร์ฟเวอร์ ลูกค้าส่งจำนวน TC เองไม่ได้
- ประวัติแต้มและ snapshot เดิมไม่เปลี่ยน สูตรรางวัลก่อนอัปเกรดเก็บใน `reward_previous_formulas` และบันทึก audit
- ค่า D เดิมยังเก็บไว้สำหรับสูตรขั้นสูงที่อ้างอิง D โดยเฉพาะ แต่สูตรตั้งต้นใหม่ใช้มูลค่า × B
- รันไฟล์ซ้ำไม่รีเซ็ต B ที่แก้แล้ว

## ตรวจสอบ

Frontend ทดสอบแท็บ B, สูตร, override เฉพาะรางวัล, การเว้นช่องกลับไปใช้ค่าประเภท, สิทธิ์เดิม และกรณี B ผิด

ฐานข้อมูลทดสอบ `tests/reward-b.integration.mjs` ใช้ PGlite ตรวจการติดตั้งจาก 004 และการอัปเกรดจาก 006, สูตรสะสมเดิม, B แยกสี่ประเภท, override, สิทธิ์ Admin, ค่าไม่ถูกต้อง, การแก้สูตรพร้อมกัน, ประวัติเดิม และการรัน SQL ซ้ำ โดยไม่ใช้ฐานข้อมูลจริง
